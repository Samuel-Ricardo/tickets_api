This document maps the Rust model structs to the SQL schema and highlights the **drift** between them — the drift is a P0 blocker (#4) and contributes to total runtime breakage of login and tasks.

## SQL schema (`sql/dev_initial/01-create-schema.sql`)

```sql
-- "user"
CREATE TABLE "user" (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY (START WITH 1000) PRIMARY KEY,
  username VARCHAR(128) NOT NULL UNIQUE
);

-- "task"  (NOTE: trailing comma in source makes this SQL invalid as written)
CREATE TABLE "task" (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY (START WITH 1000) PRIMARY KEY,
  name VARCHAR(256) NOT NULL,
  pwd VARCHAR(256),
  pwd_salt UUID NOT NULL DEFAULT gen_random_uuid(),
  token_salt UUID NOT NULL DEFAULT gen_random_uuid(),   -- <- trailing comma
);
```

Seed (`02-dev-seed.sql`): `INSERT INTO "user" (username) VALUES ('demo1');`

## Models ⇄ schema — the drift

| Rust expectation (`DbBmc::TABLE`) | SQL reality | Consequence |
|---|---|---|
| `UserService` → table `"user"`; queries column **`name`** | table `"user"` exists but the column is **`username`** | `first_by_username` (`service/user.rs:38`) runs `WHERE name = $username` → column does not exist → query fails → login fails |
| `UserForLogin` expects `pwd`, `pwd_salt`, `token_salt` on `user` | these columns are on **`task`** (lines 15-17) | every login query fails: `column "pwd_salt" of relation "user" does not exist` |
| `TaskService::TABLE = "tasks"` (plural) | table is **`task`** (singular); there is no `tasks` table | every task CRUD query fails against a nonexistent table |
| `Task { title }` expects a `title` column | `task` has `name`, not `title` | select column list mismatches |
| `Task` has no `pwd`/salts | `task` has `pwd`, `pwd_salt`, `token_salt` | salting is on the wrong entity — per-user salt isolation is unreachable |

> **Net effect:** as written, **neither login nor task CRUD can run** against this schema. The intended per-user `gen_random_uuid()` salt strategy (a good idea) does not exist in the live schema because the columns are on `task`, not `user`.

## Reconciled schema (recommended)

To match the models and restore the intended per-user salts:

```sql
CREATE TABLE "user" (
  id         BIGINT GENERATED BY DEFAULT AS IDENTITY (START WITH 1000) PRIMARY KEY,
  username   VARCHAR(128) NOT NULL UNIQUE,
  pwd        VARCHAR(256),
  pwd_salt   UUID NOT NULL DEFAULT gen_random_uuid(),
  token_salt UUID NOT NULL DEFAULT gen_random_uuid()
);

CREATE TABLE "task" (
  id    BIGINT GENERATED BY DEFAULT AS IDENTITY (START WITH 1000) PRIMARY KEY,
  cid   BIGINT NOT NULL REFERENCES "user"(id),   -- owner scoping (closes S8)
  title VARCHAR(256) NOT NULL
);
```

And reconcile the model/queries: `User.name` → query `username` (or rename the column to `name`) and `TaskService::TABLE` → `"task"`. The long-term fix is to **adopt `sqlx::migrate!()` and drop the hand-run dev SQL files**, making the schema a compile-time-checked artifact (P1 / S15). See [issue-roadmap.md](issue-roadmap.md).
